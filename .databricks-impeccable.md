## Design Context

### Surface type
Databricks App and customer-facing benchmark demo.

### Audience
External customers, partners, solution architects, and field teams.

### Theme
Dark operations-console theme, with accessible light-compatible tokens where practical.

### Use case
Configure, execute, compare, and explain Lakebase OLTP, DBSQL OLAP, and bidirectional LTAP scenarios from one frictionless control surface.

### Brand (locked)
- Palette: Lava 600 #FF3621 (10% accent), Navy 900 #0B2026, Light #F9F7F4
- Typography: DM Sans 400/500/700 + DM Mono
- Components: Du Bois first
- Voice: Databricks editorial-plain (no superlatives, plain statements)

### Additional constraints
- WCAG AA keyboard and contrast support.
- Projection-friendly information density for live demonstrations.
- Every preview dependency must have a visible readiness state and remediation path.
- Long-running tests must survive the Databricks Apps 120-second request limit through polling.

## Design Brief

### User journey
1. Open LakeLoad and verify that Lakebase, DBSQL, Unity Catalog, CDF, synced tables, Search, and telemetry are ready.
2. Prepare the deterministic retail dataset and select a scenario that explains the question being tested.
3. Launch the run, follow phase and metric updates, then inspect the result and engine guidance.
4. Compare compatible Lakebase and DBSQL results or follow the closed-loop LTAP timeline.

### Screens
1. **Setup** — shows deployment and feature readiness; the primary action prepares all supported resources.
2. **Scenarios** — presents the test catalog, configuration controls, live run state, and the primary run action.
3. **Compare** — aligns Lakebase and DBSQL results, configuration fingerprints, and the LTAP freshness path.

### Component inventory

**Du Bois patterns**
- Button, Select, Input, Tabs, Badge, Table, Tooltip, Alert: standard controls and state communication.

**Custom**
- Readiness matrix: combines feature state, ownership, and exact remediation in one scan.
- Scenario card: explains the question, expected engine fit, operation mix, and prerequisites.
- Live metric strip and time series: shows stable-width throughput, p50, p95, p99, and errors.
- LTAP timeline: shows Lakebase commit, Delta arrival, DBSQL enrichment, sync return, and serving lag.

### Content hierarchy
- Primary: current readiness or active run, with one clear action.
- Secondary: scenario purpose, configuration, and comparison metrics.
- Tertiary: resource identities, versions, timestamps, SQL text, and remediation details.

### Layout sketch

```text
┌ LakeLoad ─ environment health ─ active profile ─ documentation ┐
├ Setup │ Scenarios │ Compare                                    ┤
├──────────────────────────────┬─────────────────────────────────┤
│ Main workflow                │ Context / prerequisites         │
│ setup matrix or scenario     │ engine fit, resource state,     │
│ configuration + primary act. │ reproducibility fingerprint     │
├──────────────────────────────┴─────────────────────────────────┤
│ Live metrics / comparison table / LTAP event timeline          │
└────────────────────────────────────────────────────────────────┘
```

### Interaction states to build
- Skeleton, empty, error, success, disabled, and loading states for readiness, preparation, runs, and comparisons.
- Hover, active, and focus-visible states for every link, button, tab, input, and disclosure.
- Cancellation and polling failure recovery for long-running work.

### Responsive behavior
- Mobile (under 768 px): stacked panels, horizontally scrollable metric/table regions, full feature access.
- Tablet (768–1024 px): two-column cards where space permits; configuration and context stack.
- Desktop (1024 px and above): persistent two-column work area and full-width live metrics.

### Out of scope
- Automatic activation of workspace previews, UI-only CDF activation, irreversible Search enablement, and external OpenTelemetry collector provisioning. LakeLoad detects these states and provides exact setup steps.
